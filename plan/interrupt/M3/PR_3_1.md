# PR 标题

fix(arm-vcpu): preserve full virtual interrupt IDs

## 要解决的问题

AArch64 当前的 direct interrupt injection 路径存在四个会阻塞后续 SPI
controller 和 Router 开发的底层问题：

1. `ArmVcpu::inject_interrupt(usize)` 经过
   `ArmHostOps::inject_virtual_interrupt(u8)` 时会截断 INTID，256–1019 会被
   静默转换为 0–255。
2. GICv3 direct injection 在所有 LR 被占用时直接 panic，调用方无法恢复，
   也无法在后续模块中把中断保留到软件 pending 状态。
3. ICH LR 缺少软件 EOI overlay，`ICH_VTR_EL2.IDBITS` 的宽度错误并与
   PREBITS 重叠；legacy `Vgicd` 对高 ISENABLER 和 `fetch_irq()` 使用裸数组
   下标，访问未建模的高 INTID 时会越界。
4. AArch64 direct injection 迁移时，GICv2
   `VirtualInterruptConfig::software()` 的两个布尔参数被对调，将原有的
   Group 0、开启 EOI maintenance 错误改成了 Group 1、关闭 EOI
   maintenance，改变了兼容路径的中断分组和 EOI 通知语义。

本 PR 修复这些表示能力和失败语义，为后续 ICH capability、SPI controller、
EOI 重投和 LR refill 提供稳定边界。

## 改动内容

### 1. 新增无损 virtual INTID 类型

在 `arm_vcpu` 中新增：

- `ArmVirtualIntId(u32)`：表示传统 GIC virtual INTID `0..=1019`
- `ArmVirtualIntId::new(u32)` 和 `TryFrom<usize>`：拒绝 1020–1023、
  `usize::MAX` 等非法输入
- `as_u32()`：提供无损架构编码

不提供 `From<usize>` 或 `u8` 转换，避免重新引入静默截断。

`ArmHostOps::inject_virtual_interrupt()` 改为接收 `ArmVirtualIntId`。
`ArmVcpu::inject_interrupt(usize)` 在 host 边界前完成 checked conversion。
AxVM host adapter、assembly layout host、测试实现和中英文 README 已同步。

### 2. 增加 typed LR 表示和纯逻辑槽位规划

新增：

- `IchLrState::{Pending, Active, ActivePending}`
- `IchLrEntry::{Invalid, Software { ... }}`
- `IchDirectInjection::{AlreadyPresent, Vacant(slot)}`
- `plan_direct_injection()`：基于 LR snapshot 和 ELRSR 选择 direct-inject
  槽位

LR 编解码遵循以下规则：

- 先读取 STATE；Invalid LR 直接返回 `Invalid`，忽略 VINTID/HW 等残留位
- 有效软件 LR 验证 VINTID，并保留 state、priority、Group1 和 EOI
- 有效 `HW=1` LR 返回 unsupported；direct-inject 扫描时将其视为已占用，
  不覆盖 passthrough LR
- `Invalid` 始终编码为全零
- 空槽必须同时满足 ELRSR empty 和 LR STATE Invalid

`plan_direct_injection()` 明确只服务兼容 direct-inject 路径。后续 SPI
controller 不复用其 duplicate folding 语义，因为 edge 在 Active 状态再次
到达时需要形成 Active+Pending。

### 3. 将 LR 满载和异常状态改为 typed error

`ArmVcpuError` 使用 `thiserror`，在保留既有错误 variant 的同时新增：

- `InvalidVirtualInterruptId`
- `InvalidListRegisterCount`
- `NoFreeListRegister`
- `MalformedListRegister`
- `UnsupportedListRegister`

AxVM 错误映射如下：

| arm_vcpu 错误 | VmBackendError |
|---|---|
| 非法 virtual INTID | `InvalidInput` |
| 异常 LR count/编码 | `InvalidData` |
| 没有空 LR | `ResourceBusy` |
| 不支持的 LR 表示 | `Unsupported` |

LR 满载不再 panic，也不会覆盖 Active LR。

### 4. 迁移 AArch64 direct injection

GICv3 路径现在：

1. 读取并校验 `ICH_VTR_EL2.LISTREGS + 1`，只接受 `1..=16`
2. 获取有效 LR snapshot 和 ELRSR
3. 相同 INTID 已处于 Pending、Active 或 ActivePending 时幂等成功
4. 跳过所有非空硬件 LR
5. 无空槽时返回 `NoFreeListRegister`
6. 写入 Pending、Group1、默认 priority、EOI=false 的软件 LR
7. 必要时开启 `ICH_HCR_EL2.EN`

GICv2 保留现有 LR0 direct-inject 策略，但使用已验证的完整 INTID，不再经过
截断转换。兼容路径明确维持 Group 0 和开启 EOI maintenance；配置构造提取为
返回真实 `VirtualInterruptConfig` 的纯 helper，生产注入路径和 host 单元测试
调用同一实现，避免测试与实际 LR 配置脱节。本 PR 不把 GICv2 迁移到 GICv3 的
Group 1、EOI=false 策略。

虚拟定时器仍保留私有中断的 `u8` host API；AxVM adapter 使用 checked
constructor 转换为 `ArmVirtualIntId`，注入失败时记录错误。

### 5. 修正 ICH 字段

`arm-gic-driver` 中：

- 将 `ICH_VTR_EL2.IDBITS` 从错误的 4 bit 修正为架构定义的 3 bit
  `[25:23]`，与从 bit 26 开始的 PREBITS 保持不重叠
- 为 `ICH_LR_EL2` 增加 bit 41 的软件 EOI overlay
- 增加 raw LR 写入 helper；调用方在访问前已校验 capability 和 slot 范围

本 PR 不启用 TDIR、UIE、LRENPIE、NPIE 或 maintenance interrupt。

### 6. 修复 legacy Vgicd 越界

- ISENABLER 已建模项保持原有 enable 行为
- 512–1019 对应的合法但未建模项读取为 0、写入忽略
- 未识别的 GICD 地址继续 RAZ/WI
- `fetch_irq()` 改为返回 `VgicResult<VgicInt>`，未建模 IRQ 返回
  `VgicError::InvalidIrq`

这不是对高 INTID 的完整 controller 支持。后续 sparse SPI controller 将持有
高 INTID 的真实 pending/active/route 状态。

### 7. 整理架构条件编译与回归测试布局

根据审阅意见补充以下行为保持型整理：

- 删除通过 `include_str!` 解析 `ich.rs` 源码文本的 IDBITS 集成测试
- 在 `sys_reg::ich` 文件末尾使用普通 `#[cfg(test)] mod tests`，直接检查
  `tock-registers` 生成的 `ICH_VTR_EL2::IDBITS` 和 `PREBITS` 的 `mask/shift`
- ICH 模块仅在 AArch64 生产构建或 crate 单元测试中启用；非 AArch64 测试构建
  只提供不可执行的寄存器访问占位分支，使字段定义可以在 host 上验证，不改变
  AArch64 system register 访问路径
- `arm_vcpu` 保留修改前对 AArch64-only 实现模块的显式 `#[cfg]` 声明，将
  AArch64 专属导出、兼容别名和硬件查询函数集中到一个原生
  `aarch64_api` 模块统一导出；INTID、LR 纯逻辑和 host capability 边界继续在
  host 构建中可测试，同时不新增条件编译依赖
- 删除通过 `include_str!` 搜索 AxVM GICv2 源码常量的集成测试；在
  `src/arch/aarch64/gicv2.rs` 中新增纯配置模块，直接构造 driver 的
  `VirtualInterruptConfig`，并让生产 GICv2 注入路径复用该构造函数
- host integration test 通过 `#[path]` 编译同一份 AArch64 helper，直接检查
  真实配置的 INTID、priority、Pending state、Group 0 和 software EOI
  maintenance；这不是源码文本匹配，测试与生产路径执行同一份 Rust 实现
- helper 保持在既有 `aarch64` 架构目录内，`src/arch/` 根目录仍只包含四个
  架构目录和 dispatch page，满足 AxVM 的架构边界契约
- 测试仅复用 AxVM AArch64 路径已经使用的 workspace `arm-gic-driver` 作为
  dev dependency，不引入新的外部依赖

这项整理不改变 public API、AArch64 寄存器编码或 direct-injection 运行时语义。

## 关键设计逻辑

### virtual INTID 与 SPI ID 分层

`ArmVirtualIntId` 覆盖 0–1019，而不是只覆盖 SPI 32–1019，原因是现有
direct-inject 路径仍服务 SGI/PPI 和虚拟定时器。后续 controller 使用独立的
SPI ID 校验，避免把 private interrupt 和 SPI 状态机混在一起。

### LR snapshot 与寄存器访问分离

LR 编解码和槽位选择是纯逻辑，可在 host 上构造 snapshot 并稳定测试；
AxVM adapter 只负责读取/写入实际 ICH system register。这样既能验证 LR full、
duplicate 和 ELRSR 不一致等错误路径，也不会在测试中执行 AArch64 特权寄存器
访问。

### 不把 LR 当作 pending 真相

本 PR 仅将现有 direct injection 改为安全、可恢复的行为。LR 满时返回
`ResourceBusy`，不在本 PR 内重新排队。后续 SPI controller 才会持有 durable
pending/active 真相，并在 refill 时重试投递。

### legacy VGICD 只做安全兜底

没有把 legacy 512 项数组扩成 1020 项，因为这会形成短期的 dense controller
设计。当前修复只保证合法 MMIO 访问有确定的 RAZ/WI 行为，最终高 INTID 状态由
后续 sparse controller 接管。

## 测试

实现前先加入并确认以下回归测试在旧实现上失败：

- `arm_vcpu` 尚无无损 INTID 类型，256/1019 contract 无法编译
- `arm_vgic::fetch_irq()` 仍返回裸值，高 INTID 没有 typed error
- AxVM GICv2 可执行配置测试复现参数对调实现，并稳定在
  `config.group1 == true` 处失败

新增测试覆盖：

| 场景 | 验证内容 |
|---|---|
| INTID 0、31、32、255、256、1019 | checked conversion 和 round trip 无损 |
| INTID 1020、`usize::MAX` | 返回 `InvalidVirtualInterruptId` |
| host boundary 注入 256 | host 实际观察值为 256 |
| Invalid LR 带残留字段 | 忽略 VINTID/HW/EOI 残值 |
| 三种软件 LR state | 编解码保持 Pending/Active/ActivePending |
| VINTID、EOI、priority、Group、STATE | 使用架构规定 bit position |
| IDbits/PREbits mask | IDbits 覆盖 `[25:23]`，且与 PREbits `[28:26]` 不重叠 |
| GICv2 direct injection | 生产路径与测试共用真实配置 helper，保持 Group 0、Pending 和开启 EOI maintenance |
| HW LR 和非法 VINTID | 返回 unsupported/malformed |
| 16 个 LR 全部占用 | 返回 `NoFreeListRegister`，不 panic |
| ELRSR 与 LR state 不一致 | 只选择二者一致的空槽 |
| ISENABLER16/31 | 高 INTID 访问 RAZ/WI、不越界 |
| `fetch_irq(512)` | 返回 `VgicError::InvalidIrq` |
| AxVM error translation | 映射到正确的 backend error |
