# 7月技术报告

## 目标与问题

7 月的核心目标是完成 AxVisor 设备中断注入架构的重构（[issue #1586](https://github.com/rcore-os/tgoskits/issues/1586)）。

重构前的中断路径存在以下问题：

1. `IrqLine` 到 vCPU 注入的路径在各架构上分别演化，x86 运行时直接理解 IOAPIC、串口、PIT 细节，LoongArch 依赖架构特定队列变体。
2. 跨 vCPU 中断递送路径不统一，设备中断、IPI 和直通 IRQ 各自走不同的通道。
3. 没有一个清晰的通用边界：设备 → Router → runtime 队列 → 目标 vCPU 注入。

重构的目标是将中断路径统一为：设备只表达 `IrqLine`，由各架构 Router 决定路由，runtime 负责排队、唤醒和 host IPI，目标 vCPU 在自己的 run loop 中完成最终注入。

重构整体分为 5 个模块：所有架构共享的模块（Resource 新增 `IrqLine`、`InterruptRouter` trait、sender/dispatcher 通道等）和四个架构各自的中断 Router。

## 计划安排

### 第一阶段：共享资源与 runtime 递送通道

- [x] 为 `Resource` 增加 `IrqLine { line: u32, trigger: InterruptTriggerMode }`，使用 BTreeMap 索引建立独占 IRQ line 注册，检测同一设备重复声明和不同设备占用同一 line，bundle 注册失败时回滚已登记的 IRQ line。（#1630）
- [x] 新增 `VirtualInterruptId(u32)` 和携带 trigger mode 的 `PendingVcpuInterrupt`，避免 x86 `u8` vector 限制扩散到其他架构。（#1661）
- [x] 新增 per-vCPU `VcpuIrqDispatcher`（入队/出队/reset）和 `VcpuInterruptQueue`（FIFO、vCPU 隔离），`enqueue()` 不在锁内调用 wake/IPI/外部回调。（#1661）
- [x] 新增 `VmInterruptSender`，持有 `Weak<AxVM>`，每次发送时查找当前 runtime、不缓存 dispatcher；新增 `dispatch_vcpu_interrupt()` 按”入队 → notify → host IPI”顺序递送。（#1679）
- [x] vCPU run loop 在进入 guest 前 drain 新 dispatcher 并调用 `ArchOps::inject_vcpu_interrupt()`；迁移期继续 drain 旧 `pending_interrupts`，双队列并存。（#1679）
- [x] VM stop/reset/start 后 sender 只能发现当前 runtime，不能向旧 dispatcher 入队；runtime 不存在或 vCPU 未注册时返回明确错误。（#1679）

### 第二阶段：RISC-V 基线验证

- [x] 验证 vPLIC pending、claim、complete 和 secondary vCPU IPI。

### 第三、四阶段：AArch64 Router 和 LoongArch Router

- [ ] 将 AArch64 和 LoongArch Router 的中断路径接入 InterruptFabric

## 实现情况

### 已合入 PR

#### #1630 — `feat(axdevice): register exclusive IRQ line resources`（7-17 合入）

**要解决的问题**：AxVisor 设备资源模型只能声明 MMIO、Port I/O 和系统寄存器范围，设备使用的 IRQ line 没有进入统一资源注册流程。因此设备注册阶段无法发现：同一设备重复声明同一 IRQ line、不同设备独占同一 IRQ line、bundle 注册中途失败后已登记 IRQ line 缺少统一回滚机制。

**主要改动**：

- 在 `axdevice_base::Resource` 中增加 `Resource::IrqLine { gsi, trigger }` 变体，GSI 使用 `u32` 避免 x86 `u8` 限制扩散。
- 为设备 IRQ line 声明增加独占性校验，同一 IRQ line 被不同设备注册时返回 `RegistryError::IrqConflict`。
- Bundle 注册失败时，已登记的 IRQ line 自动回滚，不会残留部分状态。
- `DeviceRegistry::register()` 在 BTreeMap 索引中记录所有已登记 IRQ line，供后续 Router 使用。

**效果**：IRQ line 从"设备随意声明、runtime 自行协调"变成"注册时即校验、冲突立即暴露、失败自动回滚"的统一资源模型。

#### #1661 — `feat(axvm): add virtual interrupt model types and per-vCPU dispatch queue`（7-23 合入）

**要解决的问题**：跨 vCPU 中断递送缺少统一的类型系统和排队机制，为 sender/dispatcher 通道提供基础数据结构和队列。

**主要改动**：

- 新增 `VirtualInterruptId(u32)`：架构无关的虚拟中断 ID，避免 x86 `u8` vector 限制扩散到 GIC（INTID 可达 1020+）、PLIC 和 LoongArch。
- 新增 `PendingVcpuInterrupt`：携带 `VirtualInterruptId` 和 `InterruptTriggerMode`，供架构 Router 和注入路径区分 edge/level 语义。
- 新增 `VcpuIrqDispatcher`：per-vCPU 的中断分发器，提供 `enqueue()`、`drain()`、`reset()`，可独立于 VM 进行 host-test。
- 新增 `VcpuInterruptQueue`：纯队列实现，支持 FIFO 顺序、vCPU 隔离和回调通知。

**效果**：建立了架构无关的虚拟中断类型层和可独立测试的 per-vCPU 队列，为后续 sender→dispatcher→run loop 贯通提供基础设施。

#### #1679 — `feat(axvm): add VmInterruptSender and integrate dispatcher into VmRuntimeHandle`（7-27 合入）

**要解决的问题**：#1661 提供了基础类型和队列，但没有将 dispatcher 接入运行时，Router 无法使用 sender 发送中断。

**主要改动**：

- 新增 `VmInterruptSender`：Router 到 runtime 的稳定发送通道，只持有 `Weak<AxVM>`，每次发送重新选择当前 runtime，不缓存会在 stop/reset/start 后失效的 dispatcher。
- 将 `VcpuIrqDispatcher` 嵌入 `VmRuntimeHandle`，固定 `enqueue → notify_all → host IPI` 顺序，失败入队不触发回调。
- 在 vCPU run loop 中 drain 新 dispatcher，通过 `ArchOps::inject_vcpu_interrupt()` 完成最终注入。
- 保留旧 `pending_interrupts` 消费路径，迁移期先旧后新。尚无 Router producer 时新队列始终为空，不改变 Guest 行为。
- 增加 FIFO、vCPU 隔离、drain 清空、trigger round-trip、未注册 vCPU、生命周期和回调顺序测试（128 项通过）。

**效果**：贯通完整中断投递通道 `sender → dispatcher → run loop → inject`，四架构 Adapter 的 trigger 语义明确，生命周期（stop/reset/start 后 sender 只选择当前 runtime）有确定性测试覆盖。

### 未合入 PR

#### #1715 — `fix(arm-vcpu): preserve full virtual interrupt IDs`（7-28 创建）

**要解决的问题**：AArch64 direct interrupt injection 路径存在四个阻塞后续 SPI controller 和 Router 开发的底层问题：INTID 经 `u8` 转换被静默截断、LR 满载时 panic、ICH 字段错误（IDBITS 宽度与 PREBITS 重叠）、GICv2 配置 Group/EOI maintenance 参数被对调。

**主要改动**：

- 新增 `ArmVirtualIntId(u32)` 无损虚拟 INTID 类型（0..=1019），checked construction，禁止 `u8` 截断。
- 新增 `IchLrEntry`/`IchLrState` typed LR 编解码和 `plan_direct_injection()` 槽位规划。
- LR 满载返回 `NoFreeListRegister` 而非 panic。
- 修正 `ICH_VTR_EL2.IDBITS`（3 bit `[25:23]`）、增加软件 EOI overlay。
- 修正 GICv2 direct injection Group 0/EOI maintenance 配置。
- Legacy `Vgicd` 外部索引 checked，512–1019 对应未建模项 RAZ/WI。

#### #1802 — `feat(axvisor): add reproducible OVMF debug profile`（7-31 创建）

**要解决的问题**：AxVisor x86_64 Guest UEFI 启动流程缺少可复现的固件基线——setup 扫描宿主 `/usr/share/OVMF`，不同环境固件版本不一致；`VM[1] boot success` 只表示宿主启动了 VM，不能证明 guest 固件进入 SEC。

**主要改动**：

- 固定 EDK2 `edk2-stable202605` OVMF DEBUG profile（X64、DEBUG、4 MiB、COM1、关闭 SMM/Secure Boot/TPM/network）。
- 增加 manifest 与 bundle 校验（来源、构建开关、大小、地址、SHA-256、combined 关系、reset-vector 覆盖）。
- 本地 unverified 固件必须显式启用环境变量，不能误当成固定 profile。
- 固定 CODE 装载契约：地址 `0xffc84000`、大小 `0x37c000`、reset vector `0xfffffff0`。
- 增加 Guest COM1 诊断 matcher：通过 SEC phase marker 区分"固件进入 SEC"和"只启动了 VM"。
