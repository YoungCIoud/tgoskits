## 1. 中断 sender/dispatcher 通道

### 完成内容

- 合入 PR #1661 的共享基础：
  - `VirtualInterruptId(u32)`，避免 x86 `u8` vector 限制扩散到 GIC/PLIC/LoongArch。
  - 携带 ID 与 trigger mode 的 `PendingVcpuInterrupt`。
  - per-vCPU `VcpuInterruptQueue` 与 `VcpuIrqDispatcher`。
- 在 `intr/sender` 增加 `VmInterruptSender`：
  - 只持有 `Weak<AxVM>`，每次发送重新选择当前 runtime，不缓存会在 stop/reset/start 后失效的 dispatcher。
  - 对 VM 已销毁、状态不接受中断、runtime 不存在和目标 vCPU 未注册返回明确错误。
- 将 dispatcher 接入 `VmRuntimeHandle`，固定 `enqueue → notify_all → host IPI` 顺序。
- 在 vCPU run loop 中 drain 新 dispatcher，并通过 trigger-aware `ArchOps::inject_vcpu_interrupt()` 完成最终注入。
- 保留旧 `pending_interrupts` 消费路径，迁移期先旧后新，尚无 Router producer 时不改变 Guest 行为。
- 修正 trigger 兼容边界：
  - x86 edge/level 映射到 VMX/SVM backend 的 `level_triggered`。
  - AArch64、RISC-V、LoongArch 明确由 Router/controller 消费 trigger，最终架构注入不静默改变语义。

## 3. AArch64 中断 Router 设计

### 完成内容

- 明确 AArch64 emulated SPI 的 durable truth 属于 VGIC controller，dispatcher 事件只作为目标 vCPU 的 kick。
- 将实现拆为六个可独立审查的阶段：
  - 3A：无损 INTID、ICH/TDIR 字段和可恢复 LR error。
  - 3B：VGIC SPI line/pending/active 状态与固定 route。
  - 3C：per-vCPU ICH context、fold/refill、两种 EOImode、TDIR/maintenance。
  - 3D：typed route 配置、controller 共享所有权与两阶段初始化。
  - 3E：`ArmInterruptRouter → sender kick → target refill`。
  - 3F：synthetic SPI device、EL1 SMP2 Guest 与 QEMU 端到端验证。
- 设计了 INTID 256、跨 CPU 固定路由、edge、level deactivate 重投、lower 后停止和 17 路 LR pressure 的验收矩阵。
- 明确 GICv2、SGI/PPI/IPI、ITS/LPI、完整 `GICD_IROUTER` MMIO 和 GPPT/passthrough 不在本阶段扩展范围内。

### 当前状态

AArch64 Router 本周仅完成设计与 issue 拆分，尚未开始生产代码实现。`router/AArch64` 分支截至 7 月 26 日仍以共享 sender/dispatcher 和兼容性提交为基础，没有 `ArmInterruptRouter`、VGIC SPI 状态机或 SMP2 端到端用例。

## 4. 本周形成的关键结论

- 中断重构必须先稳定 sender/dispatcher，再按 AArch64、LoongArch、x86 的顺序迁移 Router，最后删除旧队列。
- AArch64 不能把 dispatcher event 当作 pending 真相，也不能从远程 pCPU 写目标 vCPU 的 banked ICH 寄存器。
- Guest UEFI 的 P0 只负责“可复现和可诊断”；ACPI、PCI、virtio-blk、INTx 和 Guest OS 启动必须分别提供 Guest 可观察证据。
- x86 Guest UEFI 的 virtio INTx 路径依赖 x86 Router，不能通过继续扩大宿主 PCI/IOAPIC 透传来绕过。
- 虚拟设备饥饿和 MSI/MSI-X 继续作为后续问题保留，不阻塞当前 Router 重构与 UEFI MVP。
