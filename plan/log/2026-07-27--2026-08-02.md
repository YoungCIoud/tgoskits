## 1. 中断 sender/dispatcher 通道收尾

### 完成内容

- 合并 `intr/sender` 分支，合入 PR #1679：
  - `VmInterruptSender`：持有 `Weak<AxVM>`，每次发送重新选择当前 runtime，不缓存会在 stop/reset/start 后失效的 dispatcher。
  - `VcpuIrqDispatcher` 嵌入 `VmRuntimeHandle`，固定 `enqueue → notify_all → host IPI` 顺序。
  - vCPU run loop 中 drain 新 dispatcher，通过 `ArchOps::inject_vcpu_interrupt()` 完成最终注入。
  - 保留旧 `pending_interrupts` 消费路径，迁移期双队列并存。
- 修正四架构 trigger 兼容边界（x86 edge/level 映射、AArch64/RISC-V/LoongArch 由 Router 消费 trigger）。

### 测试与验证

- 增加 FIFO、vCPU 隔离、drain 清空、trigger round-trip、未注册 vCPU、生命周期和回调顺序测试。
- `cargo test -p axvm --features host-test --lib`：128 项通过。
- `axvm-types` clippy 通过；`axvm` 6 组 feature clippy 通过。
- x86_64 VMX/SVM、AArch64、RISC-V 显式 AxVisor build 配置通过。

### 当前状态

M0 共享 sender/dispatcher 通道已合入 dev。四架构 Adapter 的 trigger 语义已明确，生命周期（stop/reset/start 后 sender 只选择当前 runtime）有确定性测试覆盖。尚无 Router producer，新队列始终为空，不改变 Guest 行为。

## 2. AArch64 VGIC SPI 投递基础

### 完成内容

创建 PR #1829，推进 AArch64 Router M1 的 3A–3B 阶段：

- **无损 INTID 与可恢复 LR error**：`ArmVirtualIntId(u32)` 替代 `u8` 截断，typed LR 编解码与槽位规划，LR 满载返回错误而非 panic，修正 `IDBITS` 宽度、软件 EOI overlay 和 GICv2 Group/EOI 配置反转。
- **per-vCPU ICH context 与 pin 收敛**：`IchCapabilityProfile` 按 pCPU 发现 GIC 虚拟化能力，per-pCPU registry 校验异构兼容性；`bind()`/`unbind()` 保存恢复 HCR/VMCR/APR/LR，重构 `run_vcpu()` 收敛 bind/run/unbind 到同一 `CpuPin` scope。
- **VGIC SPI 状态机**：durable truth 覆盖 trigger、enabled、pending_latch、active、inflight、deactivation，`pulse`/`set_level`/`fold`/`reconcile`/`refill` 状态转换，锁内不调外部回调。
- **delivery port 与 LR refill**：每次 guest entry 前 fold→reconcile→refill；edge 重复 pulse 合并为 ActivePending，level deactivate 后重投、lower 后停止；区分 EOImode=0/1，TDIR trap→DIR 跨 vCPU 返回 owner hint。
- **maintenance PPI**：从 FDT 发现并注册 GICv3 maintenance PPI，host-lifetime per-CPU handler。

### 当前状态

PR 已提交，尚未有 review 反馈。其中 INTID/ICH/LR 修复部分也已拆分为独立 PR #1715，本周内经过多轮 review（mai-team-app、ZR233），正在根据反馈修改中。等 #1715 合入后，本 PR 可拆分为可独立审查的增量单元（ICH context 修复 → SPI 状态机 → delivery port → maintenance PPI）。

## 3. Guest UEFI P0 可复现固件基线

### 完成内容

创建 PR #1802，为 x86_64 Guest UEFI 建立可复现、可诊断的 OVMF DEBUG 基线：

- 固定 EDK2 `edk2-stable202605` / 固定 commit，X64、DEBUG、4 MiB、COM1 debug、内置 Shell，关闭 SMM/Secure Boot/TPM/network。
- 固定产物布局：`OVMF_CODE.fd`（`0x37c000`）、`OVMF_VARS.fd`（`0x84000`）、`OVMF.fd`（`0x400000`）、`manifest.toml`。
- 增加受限 flat TOML manifest parser 与 bundle 校验（来源、构建开关、大小、地址、SHA-256、combined 关系、reset-vector 覆盖）。
- 本地 unverified 固件必须显式启用 `AXVISOR_X86_64_UEFI_ALLOW_UNVERIFIED=1`。
- 固定 CODE 装载契约：`bios_load_addr = 0xffc84000`、大小 `0x37c000`、`entry_point = 0xfffffff0`。
- 增加 Guest COM1 SEC 诊断 matcher，通过 SEC phase marker 区分"固件进入 SEC"和"只启动了 VM"。

### 当前状态

PR 已提交，尚未有 review 反馈。P0 只负责"可复现和可诊断"，不承诺 ACPI、PCI、virtio-blk 或 Guest OS 启动。
