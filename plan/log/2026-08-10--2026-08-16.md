## 2. PR #1984 — 共享 virtqueue 加固（已合入）

### 背景与问题

`axvirtio-common::VirtioQueue` 是本仓库所有 virtio 设备模型共用的唯一 virtqueue 实现（消费者为 `axvirtio-net` 和 `axvirtio-blk`）。面向不可信 guest 时存在四个缺口（issue #1979）：

1. `descriptor_chain` 链长边界 off-by-one（`>= size`），与 `follow_chain` 的 `> size` 不一致，合法全索引链被拒；
2. 三个环地址只查非零，不做对齐、溢出和互不重叠的布局校验；
3. MMIO `QUEUE_READY` 可在未验证布局上直接生效；
4. `VirtioError` 无法表达布局为何无效，transport 无法据此决策。

### 完成内容

- `queue/descriptor.rs`：统一链长边界为 `> size`，合法全索引链两条路径行为一致。
- `queue/mod.rs`：新增 `validate_layout()` / `validate_layout_with_memory()`，校验三环地址非零、对齐、`addr + size*elem` 不溢出、三区域互不重叠；环区域大小无条件包含 EVENT_IDX footer，footer 别名或越界布局被拒绝；新增 `faulted` 状态（Acquire/Release），运行期 ring/descriptor 校验失败即置位，`pop`/`complete` 及 5 条 guest-data 路径在 faulted 下拒绝且不写 guest 内存，`reset()` 清除；非 `_with_memory` 入口委托 `_with_memory` 孪生，读失败同样 latch fault；`is_valid()` 内部增加 `validate_layout()` 调用。
- `mmio/state.rs`：`QUEUE_READY` 写成为「三地址非零 + scoped guest memory 布局校验」的单一强制点；新增 `mmio_write_with_memory`，axvisor 生产路径可在真实 scoped memory 下正常置 ready。
- `error.rs`：新增 `RingMisaligned` / `RingOverlap` / `InvalidRingLayout` / `QueueFaulted` 四变体，区分「运行期故障需 reset」与「正常预配置状态」。
- `axvirtio-net`：TX/RX drain 前检查 `is_faulted()`，faulted 时停止服务并告警，不再把预读失败吞成空队列；`mmio_write_with_memory` 透传 scoped guest memory。
- `axvirtio-blk`：同步接入 `mmio_write_with_memory`，修复 scoped-memory ready 校验遗漏，避免 `NoGuestMemoryAccessor` 下队列无法 ready 的回归。
- 额外收紧：`QUEUE_NUM` 在 ring 地址已编程后被拒绝。

### 当前状态

已合入 dev。issue #1979 验收项全部满足，共享 virtqueue 对所有现有及后续 virtio 设备（net、blk MMIO/PCI）统一提供布局校验和 faulted 语义。

## 3. PR #2070 — 只读 virtio-blk-pci 数据盘（draft，阻塞中）

### 背景与目标

为 x86_64 guest 增加一块 BDF `00:03.0`、4 KiB BAR0、modern non-transitional、单 queue、INTx 的只读 virtio-blk PCI 数据盘，让 direct-boot Linux 枚举设备、只读挂载 ext4 并读取 identity 文件，最终命中 `AXVISOR_X86_PCI_BLOCK_PASSED` + `identity=axvisor-readonly-data-v1`。

### 完成内容（15 commits，58 files，+8105/−579）

1. `axdevice`：x86 PCI 函数表驱动化，新增一个 MMIO PCI 函数槽位；
2. `axvirtio-blk`：将 block 请求/配置从 MMIO transport 解耦，供 PCI transport 复用；
3. `axdevice`：新增只读 virtio-blk PCI 函数，对齐 virtio 1.x 的 capability/common-config 语义（driver_feature 只写 + mask、config_generation 机制、queue_size 初始 0）；
4. `axvm`：plan x86 virtio-blk-pci 磁盘，MP PCI 路由对齐 resolved endpoint；
5. `axvisor` + `build.rs`：加载不可变 virtio block 镜像，编译期生成、运行时只读挂载；
6. `axbuild`：生成 8 MiB raw ext4 确定性镜像，内含 `/axvisor/identity.txt = axvisor-readonly-data-v1`；
7. `axbuild` + `test-suit`：新增 `qemu-pci-block` E2E case（svm/vmx），guest 走 `enable_bios=false` + `boot_protocol="direct"`。

### 真机 E2E 验证与阻塞

在 AMD Ryzen 9 7940H（SVM）+ Docker/KVM 上，SVM/VMX 两后端结论一致：

- 外层 Axvisor 以 `uefi=true` + `to_bin=true` 启动，SVM/VMX 均成功开启硬件虚拟化；
- guest Linux direct-boot 正常，cmdline 正确携带 `axvisor.block_case=pci`；
- ACPI DSDT/APIC/FACP/SPCR 齐全，`PCI0._CRS` 正确发布 bus 0 和 4 KiB window；
- PCI 枚举成功：`pci 0000:00:03.0: [1af4:1042] class 0x018000`，BAR0 分配成功；
- virtio-pci 驱动绑定成功：`enabling device (0000 -> 0002)`。

随后 guest 写 BAR0 `device_status`（`0x80000014`，byte 写）时进入无限 NPF/EPT 循环。根因：`x86_vcpu` 的 SVM/VMX MMIO 解码器只认 LAPIC/IOAPIC 地址且只支持 dword 宽度，virtio-blk-pci BAR0 是 x86 上第一个通用 MMIO 设备，byte/word 写未被解码，RIP 不前进导致死循环。该问题 SVM/VMX 复现一致。

### 当前状态

PR 保持 draft，已在 PR body 中记录阻塞与完整 E2E 分析；计划另开 `feat(x86_vcpu): decode generic device MMIO of arbitrary width on NPF/EPT` 修复前置项，合入后再继续完成 #2070 的只读挂载、identity 读取与 INTx completion 增长验证。

### 合入后的下一步

#2070 合入后，下一步是复用同一块只读 virtio-blk-pci 设备，把它接入 OVMF 启动路径：让 guest UEFI 通过 VirtioBlkDxe 枚举到该盘，并尝试从它启动 Linux，使这条链路从 direct-boot 数据盘升级为 OVMF 可见/可启动的 virtio-blk PCI 磁盘。可写后端、实时文件后端等能力不在本 PR 范围内，留待后续独立推进。
